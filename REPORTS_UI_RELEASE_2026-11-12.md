# Reports and engineer reporting release - 12 November 2026

The Admin reports workspace now has a clean header, shorter module tabs, responsive toolbars/tables, consistent buttons, and an Engineers tab. Existing sales, project, financial, field-operations and warranty modules remain. Decorative fixed-value progress was removed; report errors now show retry states and disable exports instead of displaying successful empty figures. CSV exports quote/escape content and neutralize spreadsheet formula-like text. Explicit zero invoice balance is preserved in frontend aggregation, and manager lead assignments handle string/numeric IDs consistently.

Engineer reporting uses a new read-only `/api/reports/engineers` endpoint, restricted to administrator role 1 and querying `req.db`. It includes non-deleted role-4 engineers, even inactive or idle engineers, and non-deleted projects. Reports provide current assigned project counts/capacity, active/recorded complete counts, projects past planned end, stale project updates, authored work logs/hours, engineer/search/workload filters, default cards/list views, project drill-down and filtered CSV exports. Projects without a current engineer owner are counted separately. Installation-log storage missing expected tables/columns is explicitly unavailable, not zero; unexpected query failures return an error.

Definitions: project period is based on project creation date, current assignment is used rather than historical ownership, and authored work logs are filtered independently by work date. Completion comes from a recorded completion date or completed/handover-done/warranty stage; this is an operational status, not proof of QA or a productivity score. Past planned end requires an incomplete project and a past planned installation end date. Logged hours are recorded log values, not validated attendance. India calendar dates are used in the new backend report. Existing field/warranty modules retain their older aggregation rules; this release does not constitute a complete audit of all report data semantics.

A direct-report-route loading race was fixed: the route waits for plan features to load before deciding access. Reports remain denied when the plan lacks the reports entitlement. Other route/role rules were preserved.
