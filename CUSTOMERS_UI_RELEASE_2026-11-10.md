# Customer UI release - 10 November 2026

Customer directory and profile now use a scoped customer workspace with the existing slate/amber theme, responsive buttons/dialogs and conventional icons. Both the directory and linked profile sections offer cards and list views; cards are the default. Existing customer creation/editing, contact actions, project navigation, quotations, invoices and lead history remain accessible.

Added balance filters, sorting, 12-record client pagination, debounced server search, clear-filter and error/retry states, code/contact copying, editable notes/status/type, and an unpaid-invoice shortcut. Public invoice/proposal actions require a saved public token instead of falling back to an internal numeric ID. The customer navbar title is corrected for Admin and Manager. Add-customer form grids use the installed MUI Grid API.

The existing customer endpoint limits each search to 150 records. This release preserves server-side name/code/phone/email/city and customer-type searching, displays the limit when reached, and applies balance/sort/pagination to returned results. Summary metrics describe the current search results. Project capacity is labelled linked capacity, not commissioned capacity; payments are labelled recorded invoice payments, not bank-verified receipts. No backend/schema changes were made.

Validation: production build and scoped customer/Admin Navbar ESLint pass. Local synthetic browser checks pass for Admin/Manager at 1440, 1100, 768 and 390 px, covering directory cards/list, linked tabs, responsive containment, search, balance filters, add/edit dialogs, save error/retry, preserved assignment/status in edit payload, and load error recovery. Published-build smoke passes desktop/mobile default cards and toggles on directory/profile with all API requests intercepted; no actual customer records or external messages were changed by the tests. The pre-existing large-bundle build warning remains.
